# Work with Playbook

Read [the shared guide](../../../docs/ai-guide.md) before drafting or implementation. It contains the source map, edition rules, and review boundaries. Resolve these links from this skill directory, not the user's current working directory.

Use [the starter tasks](../../../ai/tasks.json) when they match the request. Preserve the user's own task when it differs. A supplied handoff identifies its message edition and design choices; keep those sources and their conditions together.

Work in the user's intended project. The Playbook source repository is a reference unless the user wants to adapt that checkout itself. Use existing project conventions and inspect the relevant template or component before changing it. Ask for a destination only if the intended working folder is unclear.

For a player page, produce editable files and a local preview when implementation is requested. For an email, return the requested draft or template. For a review, return findings and suggested edits without changing the draft unless asked.

Check the actual result and report what remains unresolved. Do not turn a local draft into a deployment or treat a design preference as approval of the copy.
